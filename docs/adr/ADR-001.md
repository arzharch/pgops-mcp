# ADR-001: Deny-by-default SQL classifier

**Status:** Accepted · **Date:** 2026-08-24

## Context
Agents will send arbitrary SQL. We must decide read vs write vs destructive before
execution. Any misclassification of a dangerous statement as safe is catastrophic;
over-classification is merely annoying.

## Decision
The classifier is deny-by-default: any statement it cannot confidently recognize as a
pure read (SELECT/WITH/EXPLAIN with no data-modifying CTEs, no function calls known to
write) is treated as the most-dangerous applicable class. Unknown → destructive path.

## Consequences
- False positives (safe statements requiring confirmation) are acceptable and tunable.
- Requires careful handling of CTEs with INSERT/UPDATE/DELETE inside, and volatile
  functions; both handled in Phase 2 with table-driven tests.
- Security reviewers can audit one small module instead of the whole server.
