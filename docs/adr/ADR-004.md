# ADR-004: Lock-impact analysis via heuristics + known-safe patterns

**Status:** Accepted · **Date:** 2026-08-24

## Context
Exact lock-duration simulation on Postgres is not feasible externally. But operation
classes have well-known behavior (e.g., ADD COLUMN nullable = metadata-only;
ALTER COLUMN TYPE = rewrite; CREATE INDEX = lock vs CONCURRENTLY).

## Decision
Classify each DDL step into an operation class, combine with live table size to produce
an estimate + confidence + plain-language reasoning. Where a risky step has a known safe
multi-step equivalent (NOT VALID + VALIDATE, CONCURRENTLY), propose the rewrite.

## Consequences
- Estimates are honest heuristics, never presented as guarantees.
- The pattern library grows with experience and becomes a differentiator itself.
